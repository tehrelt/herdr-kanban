# EPIC-002 — MCP-сервер для управления бэклогом

**Status:** [-] IN PROGRESS

**Priority:** P1

## Цель

Предоставить AI-агентам (Claude Code, Codex и другим MCP-клиентам) стандартизированный MCP-интерфейс поверх `stdio` для чтения, поиска и безопасного обновления эпиков и задач в `backlog/*.md` без ручного редактирования Markdown.

## Задачи

- [x] TASK-002.1 Спроектировать контракт MCP-сервера и структуру модуля
  - Определить набор tools, resources и prompts, Zod-схемы параметров и формат ошибок
  - Переиспользовать чистые функции парсинга и сериализации из `mods/kanban/parser.js` и `mods/kanban/paths.js`
- [x] TASK-002.2 Реализовать MCP-сервер поверх `stdio` транспорта (`@modelcontextprotocol/sdk`)
  - Поддержать передачу пути к бэклогу через CLI-аргумент / `HERDR_BACKLOG_DIR` и автопоиск `backlog/`, `docs/backlog/`, `.backlog/` от `cwd`
  - Реализовать безопасную запись файлов с проверкой конкурентных изменений и сохранением `CRLF`/`LF`
- [ ] TASK-002.3 Реализовать MCP tools для чтения и поиска по бэклогу
  - `list_epics` с фильтрацией по статусу, приоритету и текстовому запросу
  - `get_epic` с возвратом цели, задач, подпунктов, DoD и итога реализации
  - `search_backlog` для поиска по эпикам и задачам `TASK-*`
- [ ] TASK-002.4 Реализовать MCP tools для создания и изменения эпиков и задач
  - `create_epic` с автонумерацией через `nextEpicNumber` и генерацией имени `NNN-<slug>.md`
  - `update_epic_status`, `update_epic_priority`, `update_task_status`, `add_task` (через `addTaskAndSyncEpic`)
  - `update_epic_summary` для фиксации результата в секции `## Итог реализации`
- [ ] TASK-002.5 Добавить MCP resources и prompts для контекста агентов
  - Ресурсы `backlog://epics`, `backlog://epic/{id}` и `backlog://guide`
  - Промпты для декомпозиции описания в эпики и выполнения выбранного эпика или задачи
- [ ] TASK-002.6 Покрыть MCP-сервер unit- и интеграционными тестами (`bun test`)
  - Проверить валидацию схем, защиту от перезаписи конкурентных правок, автопоиск папки и сквозной вызов tools через MCP-клиент

## Definition of Done

- MCP-сервер запускается по `stdio` и корректно обрабатывает `initialize`, `tools/list`, `tools/call`, `resources/list` и `resources/read`.
- Все операции чтения и записи используют `mods/kanban/parser.js` и сохраняют исходное форматирование `.md` файлов.
- `bun test` проходит без ошибок, включая тесты MCP-сервера.
- В `README.md` добавлена документация по запуску и подключению MCP-сервера.
